## AVM x402 Testnet Flow

RepoPilot protects analysis routes with the official `@x402-avm/express`
middleware. The server advertises the exact scheme on Algorand Testnet and
uses GoPlausible for verification and settlement.

1. The browser sends the analysis request through `wrapFetchWithPayment`.
2. The API returns `402 Payment Required` with a `PAYMENT-REQUIRED` header.
3. Pera Wallet signs the Testnet USDC asset transfer generated by
   `ExactAvmScheme`.
4. The wrapped client retries with the official `PAYMENT-SIGNATURE` header.
5. GoPlausible verifies and settles the payment before Express runs the route.
6. The API returns `PAYMENT-RESPONSE`; the browser decodes its transaction ID
   and links to Lora Testnet.

### Required configuration

Copy both `.env.example` files to local `.env` files. Set
`MERCHANT_ADDRESS` to the real Testnet merchant account and keep
`X402_FACILITATOR_URL=https://facilitator.goplausible.xyz`. Neither `.env`
file is tracked.

The payer's Pera account must be on Testnet, opted into Testnet USDC ASA
`10458941`, funded with Testnet USDC for payment, and funded with ALGO for
transaction fees. The merchant must also be opted into that asset.

### Acceptance check

The facilitator host availability check was completed manually on August 17,
2026. Host availability alone is not payment readiness: backend startup must
also load an `exact` capability for
`algorand:SGO1GKSzyE7IEPItTxCByw9x8FmnrCDe`. Do not continue to wallet signing
if startup reports that this scheme/network pair is unsupported.

1. Confirm the payer and merchant are opted into Testnet USDC ASA `10458941`.
2. Fund the payer with Testnet USDC and enough Testnet ALGO for fees.
3. Run `npm start --prefix backend`. Continue only after x402 initialization
   succeeds and the API listens on `http://localhost:3001`.
4. Run `npm start --prefix frontend` and open `http://localhost:3000`.
5. Connect Pera Wallet in Testnet mode.
6. Request the `$0.01 USDC` Investor Score analysis and approve the asset
   transfer.
7. Confirm the result contains a non-demo transaction ID decoded from
   `PAYMENT-RESPONSE`.
8. Open the Lora Testnet link and confirm the transfer is settled to
   `MERCHANT_ADDRESS`.
9. Confirm the same transaction appears in `/api/transactions`.

Acceptance passes only when all nine checks succeed. At preparation time, the
verified host responded but did not advertise the required AVM Testnet
capability, so steps 4-9 remain gated on facilitator configuration.
